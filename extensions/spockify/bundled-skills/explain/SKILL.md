# Explain code

Explain so a competent teammate can follow.

1. One-sentence summary of what this does.
2. How it fits in (who calls it, what it returns, what it depends on).
3. Walk through the important path with the actual names from the code.
4. Call out non-obvious decisions, invariants, and failure modes.
5. If helpful, a tiny example of input → output.

Do not restate every line. Skip boilerplate. If something is unclear in the code, say so.
