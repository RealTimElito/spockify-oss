# Write documentation

Write docs that a new teammate can use.

1. Start with what it is and when to use it.
2. Show the shortest working example.
3. Document options, defaults, and failure modes that actually matter.
4. Keep it accurate to the current code. Read the implementation; do not invent flags.
5. Prefer updating existing docs over creating parallel ones.

Use plain language. Short paragraphs. Code samples that can be copied.
